# dodeed 1차 LLM 선정 근거

- 작성일: 2026-11-15
- 상세 결과: [한국어 품질 비교 보고서](../eval/2026-11-15-ko-llm-openai.md), 설계 [§8](../specs/2026-11-01-dodeed-memory-skills-scheduling-design.md)

CBT 1차 모델은 gpt-6-luna로 정한다. 실제 연결 점검 3/3을 통과했고, 한국어 식당 요청 25개에서 도구 선택과 검색 조건을 모두 맞혔으며(25/25), 25건 전체 비용은 $0.0021이었다.

## 결정

| 항목 | 내용 |
| --- | --- |
| 1차 모델 | gpt-6-luna (OpenAI Chat Completions, 모든 요청 `store=false`) |
| 백업 모델 | gemini-3.5-flash-lite (Gemini API 결제 등급만, 키는 헤더로 전송) |
| 백업 전환 조건 | 1차 모델의 시간 초과, 429, 5xx, 연결 오류, 응답 형식 오류 |
| 추론 설정 | 도구를 부르는 요청은 추론을 끈다(`reasoning_effort: none`). 웹 원문을 읽는 격리 리더는 설정값을 따른다 |
| 단가 (1M 토큰, 입력/출력) | gpt-6-luna $0.10 / $0.50, gemini-3.5-flash-lite $0.30 / $2.50 |
| 데이터 보관 (CBT) | 학습에 쓰지 않음. 남용 감시용 보관(OpenAI 최대 30일)은 처리방침과 가입 동의에 공개 |
| 선정 이유 | 가격과 추론 성능 점수, 아래 실제 점검과 한국어 품질 비교 결과 |

추론을 끈 이유: gpt-6-luna는 Chat Completions에서 추론과 도구를 함께 쓸 수 없다(OpenAI 400 오류). 추론을 끈 상태로 품질 비교를 통과했으므로 CBT는 이 설정으로 간다.

## 실제 연결 점검

gpt-6-luna 실제 API 점검 3개를 모두 통과했다. 운영과 같은 시스템 프롬프트와 출구 필터를 거쳐 호출했다.

| 점검 | 보낸 요청 | 확인한 것 | 결과 |
| --- | --- | --- | --- |
| 한국어 대화 | 안녕! 한 문장으로 자기소개해 줘. | 한글 답변, 도구 호출 없음, 토큰 사용량 기록 | 통과 |
| 식당 검색 도구 호출 | 강남역에서 혼밥하기 좋은 국밥집 찾아줘 | `search_restaurants` 호출, 인자가 검색 조건 형식에 맞음, 지역에 "강남" 포함 | 통과 (첫 시도 400 → 추론 끄기 적용 후) |
| 구조화 출력 | 여자친구랑 성수에서 파스타 먹고 싶어 | 지정한 JSON 형식, 상황 값이 정해진 목록 안, 음식 종류 채움 | 통과 |

Gemini는 결제 등급 확인 전이라 실제 호출하지 않았다.

## 한국어 품질 비교

25개 사례 모두에서 도구 선택과 검색 조건이 기대값과 일치했다. 평균 응답 1.32초, 입력 16,501 토큰과 출력 872 토큰을 썼다. 사례는 상황 3종(혼밥·데이트·가성비) 각 5개, 지역·음식·시간·인원 조합 5개, 현재 위치 요청 3개, 잡담 2개다. 사례별 결과는 [보고서](../eval/2026-11-15-ko-llm-openai.md)에 있다.

"둘이서"를 2명으로, "만 원 이하"를 10,000으로 바꾸는 등 한국어 표현을 숫자 조건으로 정확히 옮겼다.

## 한계와 다음에 확인할 것

이번 결과는 단일 도구(식당 검색)를 고르는 단순한 요청에 대한 것이다. 아래 조건에 해당하면 결정을 다시 본다.

- [ ] Gemini 결제 등급 확인 후 같은 점검과 25개 사례 비교 실행 (대화 도중 OpenAI→Gemini 전환 포함)
- [ ] 여러 단계 작업(스케줄 문장 해석, 스킬 저장 판단, 예약 흐름)이 붙으면 같은 방식으로 사례를 만들어 다시 비교
- [ ] 추론을 끈 상태에서 정확도가 떨어지면 Responses API로 전환해 추론과 도구를 함께 사용 (작업량 큼)
- [ ] 격리 리더 호출까지 포함한 검색 1회당 실제 비용 측정 (이번 비용은 오케스트레이터 호출만 포함)
