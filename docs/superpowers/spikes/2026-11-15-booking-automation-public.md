# 계획 2 실험 결과 (1부): 로그인 없이 확인한 예약 자동화

- 실험일: 2026-11-15
- 방법: Playwright 헤드리스 Chromium, 모바일 화면(412×915), 한국어. 시험용 코드는 저장소에 넣지 않았다.
- 범위: 로그인 전까지. 로그인 이후 단계와 간편결제 푸시는 2부(사용자 계정 필요)에서 확인한다.
- 지킨 선: 광고 팝업을 닫는 것처럼 보통 사용자가 하는 조작만 했다. 보호 장치를 우회하지 않았고, 비공개 내부 API를 호출하지 않았다.

캐치테이블과 네이버 예약 모두 **로그인 없이 웹에서 날짜·인원·시간 선택까지** 진행된다. 로그인은 그다음 단계에서 요구된다. 자동화 차단은 만나지 않았다.

## 결과 요약

| 질문 (설계 §7.3) | 캐치테이블 | 네이버 |
| --- | --- | --- |
| (a) 웹에서 예약 직전까지 갈 수 있나 | 로그인 전까지 됨: 가게 상세 → 날짜별 예약 가능 여부 → 인원·시간 선택 | 로그인 전까지 됨: 예약 상품 → 인원 → 날짜 → 시간 → "다음"에서 로그인 화면 |
| (b) 간편결제 푸시가 휴대폰으로 오나 | 미확인 (2부) | 미확인 (2부) |
| (c) 자동화 탐지·차단 | 만나지 않음. 광고 팝업이 클릭을 가림 | 상세·리뷰·예약은 정상. 플레이스 **목록** 페이지만 "로딩중"에서 멈춤 |

## 캐치테이블

- 홈(`app.catchtable.co.kr`)과 지도 목록은 로그인 없이 열린다. 목록 카드에 영업 시간, 최대 인원, 가격대, 날짜별 "예약 가능 / 예약 마감 / 휴무"가 보인다.
- 가게 상세(`/ct/shop/<별칭>`)에서 "예약하기"를 누르면 달력, 인원(2명~), 시간대(예: 오후 5:00~8:00)를 고르는 화면이 열린다.
- 홈과 목록에 광고 팝업이 뜨고 클릭을 가린다. "닫기" 또는 X를 눌러야 다음 조작이 된다.
- 화면 구성이 열 때마다 달랐다. 추천 목록 순서와 문구가 바뀌고, 가로 스크롤 속 요소는 화면 밖에 있어 클릭되지 않는 경우가 많았다. 미리 짠 선택자로는 단계마다 여러 번 실패했다.

## 네이버

- 네이버 모바일 검색(`m.search.naver.com`) 결과에서 가게 id를 얻을 수 있다.
- 플레이스 상세(`m.place.naver.com/restaurant/<id>/home`), 방문자 리뷰(`…/review/visitor`), 예약 탭(`…/booking`)은 로그인 없이 읽힌다.
- 방문자 리뷰 페이지에는 키워드 집계("음식이 맛있어요" 3,309명 등)와 리뷰별 방문일, 방문 횟수, **인증 수단(영수증)**, 예약 여부가 있다.
- 플레이스 목록(`m.place.naver.com/restaurant/list?query=…`)은 헤드리스에서 "로딩중"에서 멈추고 API 호출도 일어나지 않았다. 원인은 확인하지 않았다(우회 시도하지 않음). 목록 대신 검색 결과에서 id를 얻으면 된다.
- 예약 상품 페이지(`m.booking.naver.com/booking/6/bizes/<업체>/items/<상품>`)에서 "예약 신청하기" → 인원 → 날짜 → 시간을 고른 뒤 "다음"을 누르면 `nid.naver.com` 로그인 화면으로 이동한다.
- 확인한 가게는 "신청 후 확정" 방식이었다. 신청 후 가게가 확정해야 예약이 끝난다.

## 설계에 주는 의미

1. **폰 워커(에뮬레이터)는 지금 필요 없다.** 두 서비스 모두 웹으로 예약 직전까지 간다. 2부에서 로그인 이후와 결제가 웹으로 되는지 확인하면 결정이 끝난다.
2. **화면 조작은 LLM 탐색이 필수다.** 선택자 스크립트만으로는 화면 변화와 팝업 때문에 자주 실패했다. 설계 REQ-EXE-001(탐색은 LLM, 확정은 엄격하게)이 맞는 방향이다. 팝업 닫기도 탐색 단계에 포함해야 한다.
3. **네이버 방문자 리뷰를 맛 평가에 쓸 수 있다.** "인증 수단 영수증"을 근거로 영수증 인증 리뷰를 내돈내산으로 분류한다(음식점 설계 REQ-RST-010).
4. **"신청 후 확정" 예약 상태를 다뤄야 한다.** 승인 요청과 알림에 "신청됨 → 가게 확정 대기 → 확정/거절" 상태가 필요하다.
5. **대기 등록(원격 줄서기)은 미확인이다.** 캐치테이블 "웨이팅" 가게는 이번에 확인하지 않았다.
